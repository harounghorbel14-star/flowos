## Defects found

**1. Every authenticated response re-sent the session cookie (fixed).**
`createContext` added `Set-Cookie: flowos_session=…` to every authenticated
API response, not only when the session's expiry was renewed. A request
still in flight when the cookie was removed (or when the user signed out)
put the cookie back when its response arrived. In use this leaves a revoked
session cookie in the browser after sign-out: harmless to security (the
server rejects it) but wrong, and it made walkthrough step 1.5 fail
intermittently (2 of 2 full runs, 1 of 2 isolated runs).
Fix: the cookie is re-sent only when this request renewed the session
(`AuthState.renewed`). Regression test: `http.test.ts` ("re-sends the session
cookie only when the session is renewed"), which failed before the fix. After
the fix: 5 of 5 isolated runs and the full 81-step walkthrough pass.

**Observations, not changed:**

- Invalid email in the employee form shows the generic "Invalid email" (cosmetic).
- With billing disabled, the Stripe webhook path answers 404 (refused either way).

**Audit tooling fixes (not app defects):** the walkthrough used a loose
`getByLabel("Password")` that also matches the new "Show password" button,
and Playwright 1.56's `clearCookies({ name })` filter did not reliably remove
the cookie; both were corrected in the scripts.
